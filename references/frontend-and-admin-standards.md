# Frontend And Admin Standards

Use this reference only when the project has a UI. Design-token documents must use concrete tables for colors, typography, spacing, radius, elevation, icons, states, motion, and density. Admin tokens additionally cover layout, panels, tables, forms, drawers/dialogs, status, and compact density.

Visual and functional component registries must record purpose, anatomy or inputs/outputs, states, accessibility, reuse rule, source files, permission/runtime boundary, and verification. Composition patterns must define layout, ports/connectors where relevant, adaptive sizing, empty/error/loading states, and what belongs in admin configuration rather than the canvas.

Keep registries factual: link existing implementations, mark planned entries explicitly, and check the registry before introducing a new component. Do not install a UI library or implement product UI as part of Harness setup.
